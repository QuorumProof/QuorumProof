# Internationalisation (i18n) Guide — Issue #1455

QuorumProof uses [react-i18next](https://react.i18next.com/) / [i18next](https://www.i18next.com/) for all UI copy.

## Architecture

| Path | Purpose |
|---|---|
| `src/i18n/index.ts` | Initialises i18next, detects language from `localStorage` → browser, registers locales |
| `src/i18n/locales/en.json` | English (source-of-truth) |
| `src/i18n/locales/es.json` | Spanish |
| `src/i18n/locales/fr.json` | French |
| `src/components/LanguageSwitcher.tsx` | Dropdown in the Navbar |

Translation keys are namespaced by feature area:

- `nav.*` — navigation bar
- `walletGate.*` / `walletGuard.*` — wallet connection flows
- `issueCredential.*` — issue credential form
- `verify.*` — verification page
- `quorumSlice.*` — quorum slice builder
- `notifications.*` — notification centre
- `languageSwitcher.*` — language picker itself
- `common.*` — shared strings (loading, error, cancel, etc.)

## Using translations in a component

```tsx
import { useTranslation } from 'react-i18next';

export function MyComponent() {
  const { t } = useTranslation();

  return <h1>{t('nav.dashboard')}</h1>;
}
```

For interpolated values:

```tsx
// en.json: "successSub": "Credential #{{credentialId}} has been issued on-chain."
t('issueCredential.successSub', { credentialId: '42' })
```

For plurals (i18next ICU-style suffix):

```json
"badgeLabel_one": "{{count}} unread notification",
"badgeLabel_other": "{{count}} unread notifications"
```

```tsx
t('notifications.badgeLabel', { count: n })
```

## Adding a new locale

1. **Copy** `src/i18n/locales/en.json` to `src/i18n/locales/<lang>.json`.
2. **Translate** every value. Do not change the keys.
3. **Register** the locale in `src/i18n/index.ts`:
   ```ts
   import de from './locales/de.json'
   // …in i18n.init resources:
   de: { translation: de },
   ```
4. **Add** the language to `SUPPORTED_LANGUAGES` in `src/components/LanguageSwitcher.tsx`:
   ```ts
   { code: 'de', nativeName: 'Deutsch' },
   ```
5. **Open a PR** with your changes. The review checklist:
   - [ ] All keys present (no missing keys vs. en.json)
   - [ ] Interpolation placeholders `{{…}}` preserved
   - [ ] RTL direction set (`dir: 'rtl'`) for Arabic, Hebrew, etc.
   - [ ] Native speaker review or community sign-off

## Language detection order

1. `localStorage['quorumproof-lang']` — explicit user choice (persisted)
2. `navigator.languages` — browser preference list (first match wins)
3. `'en'` — fallback

Missing keys fall back to English automatically.

## Formatting dates and numbers

Use the browser's built-in `Intl` APIs which automatically respect the current locale:

```tsx
const { i18n } = useTranslation();
const formatted = new Intl.DateTimeFormat(i18n.resolvedLanguage).format(date);
```

## Testing i18n

Wrap components under test with `I18nextProvider` if you need a specific locale:

```tsx
import i18n from '../../i18n/index'
import { I18nextProvider } from 'react-i18next'

render(
  <I18nextProvider i18n={i18n}>
    <MyComponent />
  </I18nextProvider>
)
```

## RTL support

For RTL locales (Arabic, Hebrew, etc.):
- Set `dir: 'rtl'` in the `SUPPORTED_LANGUAGES` entry
- The `<html dir>` attribute is updated automatically by `LanguageSwitcher`
- Review layout with `dir="rtl"` on the root element in your browser dev tools before shipping
