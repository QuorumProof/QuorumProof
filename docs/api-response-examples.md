## Conventions

- Base URL in examples: `http://localhost:3000`.
- All bodies are `application/json` unless noted. Error bodies are
  `application/problem+json` (see [Error responses](#error-responses)).
- `u64` / `i128` values returned from Soroban are serialized as **strings**
  (the server converts `BigInt` → string before JSON encoding). Treat IDs,
  ledger numbers, and amounts as strings on the client.
- Stellar addresses are 56-char `G…` strings. Hashes are lowercase hex.
- Timestamps are either Unix seconds (`number`, fields ending in `_at` that
  come from the contract) or ISO-8601 strings (fields generated by the API
  server, e.g. `verified_at`).
- Examples below use the **unversioned** paths (`/api/...`). These currently
  route to v1 semantics; see [versioning](#response-example-versioning) for
  the v2 differences.

## Response example versioning

Every example in this file is tagged with the API version it was captured
against. When a response shape changes, the old example is kept (marked
deprecated) alongside the new one until the old API version is sunset.

| API version | Status | Path prefix | Examples tagged |
|---|---|---|---|
| v1 | Maintenance since 2026-09-01, sunset 2027-03-01 | `/api/v1/...` and unversioned `/api/...` | `v1` |
| v2 | GA since 2026-09-01 | `/api/v2/...` | `v2` |

### v1 → v2 response differences

| Aspect | v1 | v2 |
|---|---|---|
| Envelope | `{ "ok": true, "version": "v1", "data": { … } }` on versioned routes | Raw resource object, no envelope |
| Credential metadata field | `metadata` | `metadata_hash` |
| Address field | `address` | `stellar_address` |
| Pagination cursor | `next_cursor` | `cursor` |
| Errors | `{ "error": "…" }` (Problem Details fields added alongside) | RFC 9457 Problem Details only |

**Example — the same credential in both versions:**

`v1` — `GET /api/v1/credentials/42`
```json
{
  "ok": true,
  "version": "v1",
  "data": {
    "id": "42",
    "issuer": "GCEZWKCA5VLDNRLN3RPRJMRZOX3Z6G5CHCGZRXDMTGEYJ66SDOQ62RK",
    "subject": "GBVZHJRZMJXHE3RQXEKW3KRJM45OZDXOLYG35PNZGJDAZOFMFKQLM4H",
    "credential_type": 1,
    "metadata": "a3f1b2c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2",
    "revoked": false,
    "expires_at": null
  }
}
```

`v2` — `GET /api/v2/credentials/42`
```json
{
  "id": "42",
  "issuer": "GCEZWKCA5VLDNRLN3RPRJMRZOX3Z6G5CHCGZRXDMTGEYJ66SDOQ62RK",
  "subject": "GBVZHJRZMJXHE3RQXEKW3KRJM45OZDXOLYG35PNZGJDAZOFMFKQLM4H",
  "credential_type": 1,
  "metadata_hash": "a3f1b2c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2",
  "revoked": false,
  "expires_at": null
}
```

v1 responses on deprecated routes also carry `Deprecation` and `Sunset`
headers; clients should log a warning when they see them.

### Versioning rules for this document

1. A **non-breaking** change (new optional field) updates the example in
   place and adds a line to the changelog below.
2. A **breaking** change adds a new example under the new version tag and
   marks the previous one `(deprecated — vN)`. Remove it only after that
   version's sunset date.
3. Every PR that changes a response shape in `api-server/src/routes/` must
   update this file in the same PR.

## Shared response schemas

Schemas are given in TypeScript notation; `string` IDs are decimal-encoded u64.

### `Credential`

```ts
interface Credential {
  id: string;                 // u64
  issuer: string;             // Stellar address
  subject: string;            // Stellar address
  credential_type: number;    // u32, see docs/credential-types.md
  metadata_hash: string;      // hex; `metadata` in v1
  revoked: boolean;
  suspended?: boolean;
  expires_at: number | null;  // Unix seconds
  version?: number;
}
```

### `QuorumSlice`

```ts
interface QuorumSlice {
  id: string;                 // u64
  creator: string;            // Stellar address
  attestors: string[];        // Stellar addresses
  weights: number[];          // 1–100, parallel to `attestors`
  threshold: number;
  version?: number;
}
```

### `CursorPage<T>`

```ts
interface CursorPage<T> {
  data: T[];
  pagination: {
    cursor: string | null;       // cursor used for this page (base64)
    next_cursor: string | null;  // `cursor` in v2; null when no more pages
    limit: number;               // 1–100
    total: number;
    has_more: boolean;
  };
}
```

### `ProblemDetails` (errors)

```ts
interface ProblemDetails {
  type: string;     // https://quorumproof.io/errors/<slug>
  title: string;    // e.g. "Not Found"
  status: number;   // mirrors the HTTP status
  detail: string;   // occurrence-specific message
  error: string;    // v1 compatibility alias of `detail`
  instance?: string;
  [extension: string]: unknown;
}
```

### `BatchVerificationResponse`

```ts
type BatchVerificationStatus =
  'verified' | 'failed' | 'not_found' | 'revoked' | 'expired' | 'error';

interface BatchVerificationResponse {
  results: Array<{
    credential_id: number;
    claim_type: string;
    status: BatchVerificationStatus;
    proof: {
      verified_at: string;  // ISO-8601
      credential_status: 'active' | 'revoked' | 'suspended' | 'expired';
      digest: string;       // 16 hex chars, correlation id — NOT a security primitive
    } | null;
    error: string | null;
  }>;
  summary: {
    total: number;
    verified: number;
    failed: number;
    not_found: number;
    errors: number;
    duplicates_deduplicated: number;
    execution_time_ms: number;
  };
}
```

## Error responses

All error responses follow RFC 9457 Problem Details
(`api-server/src/middleware/problemDetails.ts`). The `error` field is kept for
v1 clients.

### Status code catalogue

| Status | `type` slug | When it happens |
|---|---|---|
| 400 | `bad-request` | Malformed ID, invalid query parameter, schema validation failure |
| 401 | `unauthorized` | Missing/invalid API key, bad request signature, expired OAuth token |
| 403 | `forbidden` | Caller authenticated but lacks the RBAC permission or IP is not allow-listed |
| 404 | `not-found` | Credential, slice, share token, webhook, or recovery request does not exist |
| 409 | `conflict` | Duplicate request (request de-duplication) or state conflict |
| 410 | `gone` | Share link expired/revoked; v1 route past sunset |
| 422 | `unprocessable-entity` | Well-formed request that fails business rules |
| 429 | `too-many-requests` | Rate limit, PoW challenge, or DDoS protection tripped |
| 500 | `internal-server-error` | Unexpected server or Soroban RPC failure |
| 503 | `service-unavailable` | Health check failing, circuit breaker open, contract paused |

### Examples

**400 — validation failure**
```json
{
  "type": "https://quorumproof.io/errors/bad-request",
  "title": "Bad Request",
  "status": 400,
  "detail": "limit must be between 1 and 100",
  "error": "limit must be between 1 and 100"
}
```

**401 — missing API key**
```json
{
  "type": "https://quorumproof.io/errors/unauthorized",
  "title": "Unauthorized",
  "status": 401,
  "detail": "API key required",
  "error": "API key required"
}
```

**403 — RBAC denial**
```json
{
  "type": "https://quorumproof.io/errors/forbidden",
  "title": "Forbidden",
  "status": 403,
  "detail": "Missing permission: admin:all",
  "error": "Missing permission: admin:all"
}
```

**404 — resource not found**
```json
{
  "type": "https://quorumproof.io/errors/not-found",
  "title": "Not Found",
  "status": 404,
  "detail": "Credential not found",
  "error": "Credential not found"
}
```

**429 — rate limited** (also sets `Retry-After` and `RateLimit-*` headers)
```json
{
  "type": "https://quorumproof.io/errors/too-many-requests",
  "title": "Too Many Requests",
  "status": 429,
  "detail": "Rate limit exceeded. Retry after 30 seconds.",
  "error": "Rate limit exceeded. Retry after 30 seconds.",
  "retry_after": 30
}
```

**500 — upstream Soroban failure**
```json
{
  "type": "https://quorumproof.io/errors/internal-server-error",
  "title": "Internal Server Error",
  "status": 500,
  "detail": "Soroban RPC request failed",
  "error": "Soroban RPC request failed"
}
```

**503 — unhealthy / paused**
```json
{
  "type": "https://quorumproof.io/errors/service-unavailable",
  "title": "Service Unavailable",
  "status": 503,
  "detail": "Contract is paused; try again later",
  "error": "Contract is paused; try again later"
}
```

> Contract-level error names (`CredentialNotFound`, `SliceNotFound`,
> `UnauthorizedAction`, …) are mapped to the HTTP statuses above. The full
> list of contract error codes is in [error-codes.md](./error-codes.md).

## Endpoint examples

Each endpoint lists its success response and the errors it can return. Tag

`200 OK` (also returned when `status` is `degraded`)
```json

  "status": "healthy",
```

`200 OK`


### Share links

#### `POST /api/credentials/:id/share`
Request
```json
{ "subject": "GBVZ…LM4H", "expiry_hours": 72, "permission": "view_only", "password": "optional" }
```
`201 Created`
```json
{
  "token": "000000000000002a0000000068d7a3c4…",
```

## Keeping examples up to date

- The source of truth for shapes is the route code under
  `api-server/src/routes/` and the OpenAPI spec in
  `api-server/openapi/openapi.json`. When they disagree with this file, the
  code wins — fix the example.
- Values are illustrative; addresses and hashes are truncated with `…` where
  the exact value is irrelevant.
- When adding a new endpoint, add: one success example, every error status
  it can emit, and any new schema to [Shared response schemas](#shared-response-schemas).
- Record the change in the [changelog](#changelog).
